## Bugs

1. **BLOCKER — Rename onto an existing filename silently destroys both files.** Renaming `references.bib` → `main.tex` (or `chapters/intro.tex` → `main.tex`) overwrote the target with the source's bytes and deleted the source — no warning, no confirm. Reproduced via **both** the UI rename (native prompt) and `POST /file/rename`. Data loss. Inconsistent with New-file, which *does* block duplicates ("main.tex already exists").

2. **MAJOR — Stale biblatex aux breaks all later compiles of a valid document.** Compile a doc using biblatex (the default templates do), then change main.tex to a plain article: every subsequent compile fails with `Undefined control sequence … l.2 \abx@aux@refcontext` in `.aldine-out/main.aux`, produces no PDF, and stays broken. The identical doc compiles fine (ok=true) in a fresh project, proving the leftover `.aldine-out/main.aux` is the cause — latexmk isn't cleaning aux artifacts when the package set changes. Error message is misleading (points at `\begin{document}`), and there's no UI to clear the aux dir.

3. **MAJOR — Editor/server desync after a destructive rename.** After a rename overwrote the open root file, the CodeMirror buffer kept displaying the old article while the server/compiler had the new 28-byte content (confirmed in the raw log). The editor showed stale content that no longer matched disk.

4. **MINOR — COMP-5 zoom not persisted** across reload (120% → 100%).

5. **MINOR — No project-name length cap.** `PATCH /projects/:id` accepted a 10,000-char name (200 OK) and stored it whole; home card just truncates visually.

6. **MINOR — Bad/traversal file path returns 500.** Creating `../../evil.tex` (UI) or writing a `..` path (API) surfaces "Internal server error"/500 instead of a clean 400/403. The traversal is correctly blocked (safeJoin) — only the error handling is wrong.

7. **MINOR — `GET /projects/:id/files` on a deleted project returns 500**, not 404 (the project GET correctly returns 404).

8. **MINOR/UX — Deleting the typeset-root file leaves a dangling rootFile.** UI lets you delete `main.tex` (the ROOT) with only the generic confirm; meta still points at `main.tex`, and compile then fails "root file not found" with no warning or auto-reassign.

9. **MINOR/UX — Empty project name silently rejected.** New-project dialog with a blank name just stays open — no message telling the user why.

10. **UX — Failed project-list fetch shows a misleading empty state.** During a brief server blip, the home screen rendered "No projects yet — start a paper" while 5 projects still existed server-side (no error/retry surfaced).

11. **Robustness observation — brief API unavailability under load.** The API returned connection-refused for a few seconds on two occasions (recovering on its own). Correlated with draining queued 120s infinite-loop compiles; may be tsx-watch dev restarts. Worth confirming in a production (non-dev) build.

## Guardrails that held (good)
- Zip-slip (`../../` and absolute entries) and path traversal are filtered on import and on file writes; `.git`/`.aldine*` paths return 403.
- Infinite-loop compile (`\loop\iftrue\repeat`) is killed at 120s and returns `ok=false, timedOut=true, exitCode=-1` (minor: `error`/`errors` are empty, so the client gets no message — UI shows a generic "Failed").
- Compile rate-gate: 2 concurrent allowed, extras get 429 "Too many typesets in flight".
- Per-project compile serialization isolates a runaway compile to its own project — other projects kept compiling fine.
- Empty-document, missing-`\input`, and unbalanced-environment compiles all fail cleanly with line-numbered, hinted errors.
