Aldine / Overleaf offline

Working on an Overleaf project offline, and running a LaTeX editor on your own machine

Overleaf runs in the browser, and its offline support covers short gaps: you can keep typing in the open file for 2 minutes on the free plan or 10 on a premium plan. For a flight or a week without a stable connection, you need a local copy of the project and a TeX installation. This page covers what Overleaf documents, the ways to get the project onto your machine, and a working local setup.

Written by the Aldine project, so read it with that in mind. Statements about other products are taken from the linked pages of that product's own documentation. Checked on 24 November 2026.

What Overleaf does when the connection drops

Overleaf's page on working offline starts plainly: "Overleaf currently offers basic support for working offline. A more advanced offline editing experience is in development." (Overleaf docs: working offline, as of November 2026) From the same page:

  1. When the connection is gone for more than a moment, a "You're offline" message appears at the top of the editor. You can go on editing the current file.
  2. How long depends on the plan. "Users on any of our premium plans can edit for up to 10 minutes while offline. Users on the free plan can edit for up to 2 minutes."
  3. When that time runs out, an "Editing paused" banner appears and the editor locks.
  4. Back online, the edits sync. If a collaborator changed the same file in a conflicting way, Overleaf shows what you typed and lets you save it as a new file or discard it.

Switching files, compiling, adding comments and the AI features are not available while offline. Overleaf also backs up offline edits in the browser, so a crashed tab may be recoverable. The catch: you have to restore that original tab (from browser history, say), not just open the project again, and it does not work in private or incognito windows.

Does Overleaf autosave?

Yes. In Overleaf's words, "Your edits on Overleaf are sent back to the server every few seconds and saved." (Overleaf docs: collaborating in Overleaf, as of November 2026) There is no save button to remember.

How far back you can go is a separate question. "For users on our free plan, the History panel will show edits made in the last 24 hours as well as any labeled versions." Full project history is a premium feature, and it follows the project owner's plan. (Overleaf docs: history and versioning, as of November 2026) On the free plan, then, labelling a version before a big change is the way to keep a restore point past a day.

Four ways to get the project onto your machine

Overleaf's offline page names these for longer periods away, and notes that "Dropbox, Git and GitHub integrations are premium features, available on paid plans." (Overleaf docs: working offline, as of November 2026)

Source ZIP. In the editor choose File, then "Download as source (.zip)", or use the "Download .zip file" button in the project list. Overleaf's page on this names no plan requirement. (Overleaf docs: downloading a project, as of November 2026) The offline page warns to "Take care with any tracked changes or comments that could become lost during this process." Copying files back by hand also overwrites whatever a co-author changed in the meantime, so tell them you have the paper.

Dropbox. Overleaf describes two-way updates: Overleaf changes go to Dropbox, and changes in the Dropbox folder come back. Files always land in Apps, then Overleaf, in your Dropbox, and every active project you can edit is synchronized. (Overleaf docs: Dropbox, as of November 2026)

Git and GitHub. Both are covered step by step elsewhere on this site: cloning an Overleaf project with git (token, username, common errors) and Overleaf's GitHub sync.

A local setup that builds the same PDF

Once the files are on disk you need two things: a TeX distribution and an editor.

1. Install a TeX distribution

  • TeX Live "provides a comprehensive TeX system" for GNU/Linux, macOS and Windows, supported by the TeX Users Group. (TeX Live, as of November 2026) The full scheme is large but means a missing package is rarely the problem.
  • MiKTeX is "a modern TeX distribution for Windows, Linux and macOS", and its package manager "installs missing components from the Internet, if required". (MiKTeX, as of November 2026) Useful on a small disk; less useful on a plane, since a package it has not fetched yet cannot be installed offline.

2. Pick an editor

  • VS Code with LaTeX Workshop. The extension builds LaTeX (BibTeX included) to PDF automatically on save, shows the PDF in VS Code or a browser, and jumps between source and PDF with SyncTeX in both directions. (LaTeX Workshop README, as of November 2026)
  • TeXstudio, "an integrated writing environment for creating LaTeX documents", with syntax highlighting and a built-in viewer. It is open source and available for all major operating systems. (TeXstudio, as of November 2026)

3. Or compile in a Docker container

If you would rather not install TeX at all, the Island of TeX project publishes TeX Live images on Docker Hub as texlive/texlive, with a full installation minus documentation. (texlive/texlive on Docker Hub, as of November 2026) Pull it while you still have a connection, then from the project folder:

docker run --rm -v "$PWD":/work -w /work texlive/texlive:latest latexmk -pdf main.tex

Replace main.tex with your root file. If the project uses XeLaTeX or LuaLaTeX in Overleaf's settings, use -xelatex or -lualatex instead of -pdf, or the output will differ.

A browser editor that runs on your machine

The setups above work well for one author. What they do not give you is the Overleaf-style browser editor with co-authors typing in the same file. Aldine, an open-source, self-hosted collaborative LaTeX editor, is one way to get that on your own machine.

Its quick start is a single docker-compose.yml with two containers, the app and a TeX Live compiler. After docker compose up -d you open http://localhost:8080; nothing needs a server or an account. (Aldine README: quick start) Plan for the first pull, though. The compiler image is about 2.4 GB to download and about 5 GB on disk, so do it before you leave.

  • Bring the Overleaf project. Download it as a source ZIP and drop it on the home screen. Aldine detects the root file and typesets it.
  • Each project is a git repository. Publish it to GitHub, GitLab, Gitea or Forgejo, and a co-author can clone it and keep editing locally in VS Code; their commits come back with one Pull. (Aldine README: features)
  • Dropped connections. Against a remote instance, the editor shows Saved, Saving…, or Offline and "Not saved"; editing goes on and the edits are saved once the connection is back. (Aldine changelog, 1.9.0)

The limits, plainly. Aldine is self-hosted only, with no hosted service today. It is young: first release July 2026, 1.0 in October 2026. Review works through comments with suggested edits and git diffs, with no keystroke-level track changes. A copy on your laptop is also a copy only you can reach, unless you share it through a git remote or run it on a server; the self-hosting guide covers that.

When Overleaf is the better choice

  • Your offline gaps are short. A few minutes of typing is covered by Overleaf's own offline mode, and the edits sync back. (Overleaf docs: working offline, as of November 2026)
  • You already pay for a premium plan. Then Dropbox or git keeps a local copy in step with the project and you need nothing else.
  • You do not want to install or run anything. overleaf.com needs only a browser; every local route here needs a TeX installation or Docker.
  • You need track changes. Overleaf has them as a premium feature. (Overleaf docs: track changes, as of November 2026)

Common questions

Can I use Overleaf offline?

For a short while. After the connection drops you can keep editing the current file for up to 2 minutes on the free plan and up to 10 minutes on a premium plan, then the editor locks until you reconnect. For longer, Overleaf's documentation suggests a local copy via download, Dropbox, git or GitHub.

Does Overleaf autosave?

Yes. Overleaf's documentation says your edits are sent back to the server every few seconds and saved. Edits made while briefly offline are synced back when you reconnect, in most cases automatically.

Does Overleaf have version control?

It has its own project history, which is not git. On the free plan the History panel shows the last 24 hours plus labelled versions; full history is a premium feature. Git integration and GitHub sync are premium features too.

Is there a local LaTeX editor like Overleaf?

For one person, TeX Live or MiKTeX plus VS Code with LaTeX Workshop, or TeXstudio, gives you an editor with a PDF preview on your machine. If you want the browser editor with live collaboration, Aldine runs locally with Docker Compose and opens on localhost:8080.
