How to choose a collaborative LaTeX editor for a research group

Most groups pick on two questions: can everyone edit the same paper at once, and who runs the server. After that, the choice turns on review, history, references, compile limits, sign-in and cost. This page goes through those criteria one at a time and says, for each, which editor documents what. Overleaf, CoCalc, TeXlyre, Papeeria, Aldine and a plain git setup with VS Code are covered.

Written by the Aldine project, so read it with that in mind. Statements about other products are taken from the linked pages of that product's own documentation. Checked on 24 November 2026.

The editors on this page

We included a tool only if its own site confirmed the facts below today. That leaves seven entries. Prices are as the vendors' pages showed them on the day we checked.

  • Overleaf calls itself "an open-source online real-time collaborative LaTeX editor". It runs a hosted version at overleaf.com, and you can run your own, either the open-source Community Edition or Overleaf Server Pro. (Overleaf repository README, as of November 2026)
  • CoCalc is a hosted platform for Jupyter, SageMath, terminals and LaTeX. (CoCalc docs: LaTeX editor, as of November 2026)
  • TeXlyre describes itself as "A local-first LaTeX & Typst web editor with real-time collaboration & offline support". (TeXlyre README, as of November 2026)
  • Papeeria is an online LaTeX editor that needs only a browser: "Full TeX Live environment is already installed and ready to run." (Papeeria home page, as of November 2026)
  • Aldine is the open-source, self-hosted editor this site is about.
  • git with VS Code and LaTeX Workshop, the local route, with no web editor at all.

If you came looking for Crixet, see Crixet and OpenAI Prism below.

Real-time co-editing

Start here, because it splits the field. Every web editor on this page lets several people type into the same file at once. The local route does not.

On overleaf.com the number of people who can edit depends on the plan. The plans page lists "Collaborators per project" as "1 user" on the free plan, 10 on Student and Standard, and "Unlimited" on Pro. (Overleaf plans, as of November 2026) Viewers are unlimited on every plan; the limit counts editors and reviewers. (Overleaf docs: premium features, as of November 2026) For a group of five on the free plan, that matters, so the page on Overleaf's free plan goes through it in detail.

Papeeria's home page says: "No collaborator count limits!" (Papeeria home page, as of November 2026) CoCalc's feature page says "Collaborators edit the same document in real time." (CoCalc: LaTeX editor, as of November 2026) TeXlyre syncs edits through Yjs over peer-to-peer WebRTC connections, with live cursors and a chat. (TeXlyre README, as of November 2026)

In VS Code the usual answer used to be Live Share. Microsoft's page now says the Live Share extension for VS Code "remains in maintenance mode, with no new features planned." (Microsoft Learn: What is Live Share?, as of November 2026) So with the local route, plan on asynchronous work through commits.

Comments and review

Two different things hide under "review". Comments let a co-author say something about a passage. Track changes records each edit so the author can accept or reject it. Groups that supervise theses tend to want both.

Overleaf's comments are "tied to specific lines of code in the editor", with replies, resolving and @-mentions. (Overleaf docs: commenting, as of November 2026) The plans page does not list comments, so we cannot tell you from it which plans include them. Track changes is clearer: "Track Changes is a premium feature." (Overleaf docs: track changes, as of November 2026) If you self-host, Overleaf's comparison lists "Commenting" and "Real-time track changes" for Server Pro and not for Community Edition. (Server Pro vs. Community Edition, as of November 2026)

TeXlyre "supports inline comments and tracked changes for collaborative review", and tracked insertions and deletions can be accepted or rejected in a review panel. (TeXlyre README, as of November 2026) Papeeria lists "discussions in the margin". (Papeeria home page, as of November 2026)

CoCalc's two pages read differently here. The feature page says "discussions attach to specific lines" (CoCalc: LaTeX editor, as of November 2026), while the LaTeX documentation still lists comments that "do not become a part of the source code" as a future plan and points to TimeTravel and Side Chat in the meantime. (CoCalc docs: LaTeX editor, as of November 2026) Try it with a test project before you rely on either.

History, version control and git

History lets you see who changed what and go back. Git goes further: branches, a copy on your own git host, and co-authors who can work outside the browser.

On overleaf.com, "Document history and version control" is "previous 24 hours only" on the free plan, with full history on the paid ones; Git, GitHub and Dropbox appear among the integrations of the paid plans. (Overleaf plans, as of November 2026) Community Edition includes "Full project history" but not "Git integration", which is in Server Pro. (Server Pro vs. Community Edition, as of November 2026) How that integration works, including what it does not carry over from git, is on using git and GitHub with Overleaf.

Papeeria has "Per-file edit history" and project snapshots. (Papeeria home page, as of November 2026) On its free plan the file history "covers last 24 hours" and git sync works with public repositories; the paid plan extends history to 30 days and adds git sync for private repositories. (Papeeria pricing, as of November 2026)

CoCalc offers TimeTravel to "go back to a working version", and "you can also use git in a Linux Terminal to track your changes". (CoCalc docs: LaTeX editor, as of November 2026) TeXlyre can back a project up to GitHub, GitLab, Gitea or Forgejo (Codeberg); this "only activates when you explicitly enable them and provide your own token." (TeXlyre README, as of November 2026)

With the local route, history simply is git.

Reference managers

If the group shares a Zotero library, check this early. It's easy to overlook and annoying to work around.

Overleaf says "You can link your ReadCube, Mendeley and Zotero accounts to your Overleaf account", as a premium feature, and notes that "only the project owner can re-sync the imported file." (Overleaf docs: premium features, as of November 2026) Its on-premises comparison does not mention reference managers. TeXlyre has a Zotero and OpenAlex panel for reference search, import and update. (TeXlyre README, as of November 2026) Papeeria lists Mendeley integration on its paid plan. (Papeeria pricing, as of November 2026) CoCalc's LaTeX pages say bibliographies "live in the same project" and that latexmk handles BibTeX, but name no reference manager. (CoCalc: LaTeX editor and CoCalc docs, as of November 2026)

Locally, LaTeX Workshop offers "completions for bibliography keys" from your .bib files. (LaTeX Workshop README, as of November 2026) The three common ways of keeping that .bib in step with Zotero are on using Zotero with LaTeX.

Compile environment and limits

A thesis with many TikZ figures can take a while to typeset. Look at where the compile runs and how long it may take.

Overleaf's plan limits table reads "Compile timeout | 10 seconds | 240 seconds" for the free and premium plans. (Overleaf docs: plan limits, as of November 2026) What to do when a compile hits that limit is on the Overleaf compile timeout page. On a self-hosted Overleaf, "Sandboxed Compiles" are listed for Server Pro, not Community Edition, and the README says Community Edition "is intended for use in environments where all users are trusted". (Server Pro vs. Community Edition and Overleaf README, as of November 2026)

CoCalc uses latexmk by default, lets you change the build command, and can run PythonTeX, SageTeX and Knitr during the build. (CoCalc docs: LaTeX editor, as of November 2026) If your papers embed computed results, that is the feature to look at. TeXlyre compiles in the browser with WebAssembly engines (pdfTeX, XeTeX and LuaTeX through SwiftLaTeX and BusyTeX), so there is no compile server. (TeXlyre README, as of November 2026) Papeeria ships a full TeX Live (Papeeria home page, as of November 2026), and its paid plan adds "auto compiling and priority compiling". (Papeeria pricing, as of November 2026) On your own machine, LaTeX Workshop will "Build LaTeX (including BibTeX) to PDF automatically on save", with whatever TeX distribution you installed. (LaTeX Workshop README, as of November 2026)

Hosting: cloud or self-hosted

A cloud editor means nobody in the group has to run a server. Self-hosting means your institution holds the files and someone has to look after the machine. Neither is free of work.

Overleaf offers both. Community Edition is AGPL-3.0; Server Pro is licensed separately through Overleaf's sales team, and "An Overleaf Pro plan subscription will not grant you access to, or a license for, Overleaf Server Pro." (Overleaf README and Server Pro vs. Community Edition, as of November 2026) CoCalc sells hosted memberships and also lists CoCalc Plus, which "runs on your own computer", and CoCalc Star for a machine you control. (CoCalc pricing, as of November 2026) TeXlyre sits somewhere else entirely: "All your data stays in your browser", collaborators connect peer to peer, and "You can run your own signaling servers". (TeXlyre README, as of November 2026) Papeeria is a hosted service.

The self-hostable options get a fuller comparison, with install footprint and licences, on Overleaf alternatives you can self-host. For Overleaf's own editions specifically there is self-hosting Overleaf: what Community Edition includes.

Sign-in and SSO

Universities often want people to log in with their institutional account, and IT departments may require it. On overleaf.com the Organizations plan lists "SAML SSO (single sign-on)". (Overleaf plans, as of November 2026) Separately, institutional SSO is "offered by some Overleaf Commons subscribers" and "is implemented using the SAML2 standard". (Overleaf docs: institutional SSO, as of November 2026) For self-hosting, Server Pro has "Single sign-on (SSO) via SAML 2 and LDAP"; Community Edition does not. (Server Pro vs. Community Edition, as of November 2026)

TeXlyre's README describes no account system; projects are shared peer to peer. (TeXlyre README, as of November 2026) We did not find SSO documented on the CoCalc or Papeeria pages we checked. Our single sign-on page covers OpenID Connect for a self-hosted editor.

Cost model

Overleaf has a free plan and paid Student, Standard and Pro plans, billed yearly or monthly, plus an Organizations plan through its sales team. (Overleaf plans, as of November 2026) Prices vary by region and change over time, so take them from Overleaf's plans page, not from us.

CoCalc describes its free tier as "just enough resources to explore the platform and do basic work" and sells memberships plus team and organisation licences. (CoCalc pricing, as of November 2026) Papeeria has a free plan, "Free forever", with "One active private project" and "Unlimited collaborators per project", and a paid plan that raises the number of private projects. (Papeeria pricing, as of November 2026) Each vendor's pricing page is authoritative.

TeXlyre's README states no price; the project is AGPL-3.0 and funded by NLnet through the NGI0 Commons Fund. (TeXlyre README, as of November 2026) Self-hosting software that costs nothing still costs a server and someone's time. Budget for that.

Offline and local editing

Trains, planes, conference Wi-Fi. Overleaf's plans page lists an "Offline editing duration" of "2 minutes" on the free plan and "10 minutes" on paid plans (Overleaf plans, as of November 2026), and its premium git integration "allows you to work offline and synchronize your files whenever you come back online." (Overleaf docs: premium features, as of November 2026) Papeeria says "You can download projects as ZIP archives at any moment and work offline with your local TeX distro." (Papeeria home page, as of November 2026) TeXlyre is built for this case: local-first, installable as a PWA. (TeXlyre README, as of November 2026) And the local route is offline by default, with sync whenever you push.

Crixet and OpenAI Prism

Crixet was a cloud LaTeX editor. OpenAI's announcement of 27 January 2026 says "Prism builds on the foundation of Crixet, a cloud-based LaTeX platform that OpenAI acquired". The same page now carries a notice: "Prism will shut down on January 1, 2027." (OpenAI: Introducing Prism, as of November 2026) When we checked, crixet.com redirected to OpenAI's Prism page. Given the announced date, we have left both out of the comparison. If you have projects there, the notice asks you to export them before the shutdown.

Where Aldine fits

Aldine is an open-source (AGPL-3.0), self-hosted collaborative LaTeX editor that runs as two Docker containers with one SQLite file by default. Against the criteria above:

  • Real-time editing with Yjs and live cursors, and no limit on collaborators.
  • Review as anchored, threaded comments, optionally with a suggested replacement the author accepts in one click.
  • Git underneath. Every project is a real git repository with branches you create and merge in the UI, and push and pull to GitHub, GitLab, Gitea or Forgejo. A co-author can clone it and keep using VS Code; their commits come back with one Pull.
  • Zotero for a whole library or one collection, personal or group, with no premium tier.
  • Compiles in a sandboxed TeX Live container with no network access. The timeout is yours to set (COMPILE_TIMEOUT_MS, 120 seconds by default).
  • Sign-in with your own OpenID Connect provider, Google, GitHub, ORCID, or email and password.
  • Cost: free to self-host, with no paid plan.

The limits are real. Aldine is self-hosted only (there is no hosted service today), so someone in the group has to run it. It is young: first release in July 2026, 1.0 in October 2026. It has review comments with suggested edits but no keystroke-level track changes, and one app node is the supported topology. The self-hosting guide lists them all and walks through the install. If your group wants an AI assistant in the loop, the optional MCP server for Claude is described separately.

When another tool is the better choice

  • Nobody wants to run a server. Then pick a hosted editor: overleaf.com, CoCalc or Papeeria. Aldine has no hosted service.
  • You need keystroke-level track changes. Overleaf has them on premium plans and in Server Pro, and TeXlyre has tracked changes too. Aldine does not.
  • Your co-authors are already on Overleaf. Switching tools in the middle of a paper has its own cost. Overleaf dates from 2011 (Overleaf: about, as of November 2026), so most collaborators will know it.
  • Your papers run code. CoCalc's SageTeX, PythonTeX and Knitr support, next to notebooks and a terminal in the same project, is built for that.
  • You want no server and offline-first work. TeXlyre keeps everything in the browser and compiles there.
  • Everyone in the group already uses git. VS Code with LaTeX Workshop needs nothing hosted beyond a remote.

Common questions

Is there a free collaborative LaTeX editor?

Several. Overleaf and Papeeria have free plans with limits listed on their own pricing pages; CoCalc has a free tier. TeXlyre, Overleaf Community Edition and Aldine are open source under AGPL-3.0, and you run Community Edition and Aldine on your own server.

Which collaborative LaTeX editors can I self-host?

Overleaf Community Edition, Overleaf Server Pro (licensed separately), Aldine and TeXlyre. CoCalc offers CoCalc Plus for your own computer and CoCalc Star for a machine you control. The page on self-hostable Overleaf alternatives compares these in more depth.

Is there an open-source collaborative LaTeX editor?

Yes. Overleaf's repository, which is the Community Edition, is released under AGPL-3.0, and so are TeXlyre and Aldine. CoCalc publishes its source under the Microsoft Reference Source License, which is a different kind of licence; check its terms before you plan to run it yourself. (CoCalc repository, as of November 2026)

What happened to Crixet?

OpenAI acquired it, and its announcement of 27 January 2026 says Prism builds on Crixet. crixet.com now redirects to OpenAI's Prism page, and the same announcement carries a notice that Prism will shut down on January 1, 2027.

Can a group work in LaTeX without a web editor?

Yes, with a shared git repository and a local editor such as VS Code with LaTeX Workshop. Collaboration is then asynchronous: each author compiles locally and changes travel as commits.
